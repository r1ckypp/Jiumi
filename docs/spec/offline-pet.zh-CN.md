# 离线桌宠、动作素材与社区插件

[English](offline-pet.md) · **简体中文**

## 基本约定

用户拿到一只宠物后，断网也能打开、抚摸和播放已安装的动作与插件。纯 H5 交付一个可直接双击的 HTML，内嵌播放器、角色素材和所选插件的可执行产物。桌面版使用相同的角色包和反馈语义，发行包自带所需组件。基础运行以浏览器或操作系统为边界，无需用户另外安装语言运行时、启动服务或登录。构建时的 TypeScript 编译、制作时可选的生图服务和发布后的运行依赖分开处理。

现有 Skill 已附离线制作器，支持单张 PNG、调色、动作试播和导出。开发时可通过 CLI 启动 macOS 窗口，也可提前编译自包含 .app 供离线运行。现有扩展以 JSON 规则表达，事件仲裁见[事件规范](event-feedback.zh-CN.md)。下文记录设计目标，当前交付范围及测试入口见文末。

## 1. Skill 制作动作，宿主播放动作

保留用户确认的主形象作为静态封面。用户已有逐帧 PNG 或精灵图时优先采用原素材。缺少动作且宿主 Agent 支持生图时，用确认过的形象作参考，先制作待机眨眼和被摸反馈两组。Skill 负责检查轮廓、比例、透明背景及脚底对齐，再交付预览。用户可补充其他动作。生图不可用、某组帧生成失败或用户跳过时，保留已确认的帧，仅对缺少的动作使用现有单图动效。离线播放器无需生图凭据。

首项实现从逐帧 PNG 着手。建议在角色包新增可选动作表，以现有动作名索引，记录有序图帧、每帧时长和循环方式。素材应随包携带。精灵图可由制作器切成相同的内部表示。旧包缺少动作表时继续按原方式播放。事件到意图、意图到动作的映射沿用现有调度器；例如摸小鸡与摸小猪都触发 pet.tap，具体表现分别由它们自己的被摸动作决定。

制作器应允许预览单组动作、调速、替换或移除帧，并标明当前使用自制帧还是单图回退。导出的 HTML 与可继续编辑的角色包须包含相同的已确认素材、播放参数和角色 UUID。动作格式见[角色包 Schema](contracts.schema.json)。

## 2. 本地插件接入桌宠生命周期

插件作者用 TypeScript 编写一段职责单一的模块，例如“专注计时结束后，请宠物招手”。发布时编译为浏览器可执行代码，将静态依赖和资源一起打包；同时附插件 ID、版本、宿主接口版本及所需能力。已安装的插件在用户机器上执行。现有 JSON 反馈规则可以继续用于简单的事件映射。

| 宿主时机 | 插件可做的事 | 宿主责任 |
|---|---|---|
| 启用、启动 | 读取本插件状态，订阅感兴趣的事件 | 每个实例只挂载一次 |
| 就绪、收到事件 | 请求动作、粒子或提醒 | 仲裁动作优先级，执行效果 |
| 隐藏、休眠 | 暂停视觉反馈，保存必要进度 | 通知插件并停止无用刷新 |
| 显示、唤醒 | 根据当前事实恢复，例如检查截止时间 | 恢复时避免重复触发旧反馈 |
| 停用、退出 | 保存状态并释放资源 | 取消订阅和计时器，隔离故障插件 |

插件通过宿主提供的窄接口订阅事件、请求反馈和读写自己的状态。发行第三方代码前，需验证执行隔离能在两个宿主中实际限制网络、宿主页面和原生桥访问，插件报错或卡住时宿主仍可交互。TypeScript 类型与权限声明用于描述接口，执行限制由宿主落实。纯 H5 无法提供的系统能力由桌面宿主或显式安装的本机适配器承担；在 H5 中只停用依赖该能力的功能。

## 3. 社区分发和事件接入

用户从本地文件导入指定版本的插件包。用户选择插件和版本后，宿主检查兼容性、所需能力与包的完整性，将产物保存到本机。H5 导出时一并内嵌，桌面版从本机加载。更新由用户触发，失败时保留可用版本。

示例路径为“助手发出等待确认 Hook → 本机适配器转换为 agent.input_requested → 宿主分发 → 插件请求提醒 → 当前角色播放等待动作”。若已有相应事件源，安装新的提醒插件即可改变反馈。接入全新工具时才需要实现适配器。

首版社区代码插件以离线能力为范围。未来有明确用例时，再单独设计经宿主代理的联网能力，说明用途、允许目的地和传输数据，由用户单独启用、随时撤销。拒绝授权或断网时，基础桌宠和其他离线插件继续运行。

## 4. 哪些状态需要恢复

| 数据 | 保存与恢复 |
|---|---|
| 角色 ID、外观、动作帧、插件选择和版本 | 属于作品，随本地可编辑角色包迁移。改单个动作、换形象或接回作品均沿用 UUID。 |
| 插件持久状态 | 按角色 ID、插件 ID 隔离，记录状态格式版本。例如计时器保存截止时间，恢复时只结算一次。插件应说明哪些数据随作品迁移。 |
| 本机窗口位置、事件源绑定、权限和凭据 | 留在设备；换设备后按需重新绑定或授权。 |
| 当前帧、瞬时抚摸、助手是否仍在等待 | 当前实例持有；重新连接时由事件源报告最新事实，避免重播上次会话的提醒。 |

桌面宿主可自动写入本机持久状态。单文件 H5 可用浏览器存储保存本机草稿，但浏览器对本地文件的存储行为有差异，便携恢复以显式导出的角色包为准。插件版本暂不可用时保留选择和数据，允许用户先打开角色。

## 离线验收

| 能力 | 验收方式 | 测试入口 |
| --- | --- | --- |
| 制作与导出 | 用自带 PNG 定制动作，导出后断网打开，核对角色 ID 和动作帧。 | `tests/offline_maker.py` |
| 插件和宿主 | 测试计时器启停、唤醒后一次性结算和插件失败回退，验证 macOS 独立应用。 | [插件 SDK](plugin-sdk.zh-CN.md)、`tests/offline_modules.py`、`tests/desktop_bundle.py` |
| 本地事件 | 用户启用的 hook 能触发反馈，断开后停止投递。 | `tests/event_bridge.py` |

当前支持 PNG 帧序列，每个可执行插件可持久化一个安全整数。macOS 可构建本机架构的独立应用，Windows 和 Linux 使用 HTML。自动切分精灵图、联网能力和应用商店发行属于后续方向。

### 角色动作库

每只宠物可携带最多 256 个命名 PNG 动作，所有动作帧编码后的总预算仍为 8 MB。可用 label 设置显示名。制作器的动作帧面板可输入新的标识，例如 wing-wave，再选择按序排列的 PNG。普通宠物可继续只用一张图。

角色包通过 `"motionPools":{"working":["typing","inspect"],"held":["dangle"]}` 声明候选动作。动作名可指向帧序列或内置动作。进入状态时选择一段，持续状态在播完时重新选择，有其他候选时避开上一段；一次性反馈播完一遍就交回控制权。显式外观映射优先。缺少的动作会跳过，无有效候选时使用原有回退逻辑。状态机也可以按自定义名称请求动作池。预览、离线 HTML、桌面应用和存档均沿用这份动作库。
